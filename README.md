# ナゴヤ人間 — Official Site

名古屋・愛知の公式資料と街の変化を、暮らす人の視点から読み解く独立メディア「ナゴヤ人間」のオフィシャルサイトです。

**正規URL（本修正の設定）**: https://nagoya-ningen.pages.dev/

## 構成

```
.
├── index.html        # トップページ
├── news.html         # お知らせ一覧
├── contact.html      # 問い合わせ窓口
├── annai/            # 記事アーカイブを使うAI案内所
├── meieki/           # 名駅の論点マップ（現在は募集休止中）
├── credits.html     # 写真の出典・利用条件
├── css/brand.css     # ブランドサイト共通スタイル（2026-09刷新）
├── css/style.css     # 既存ページ用スタイル（保持）
├── js/brand.js       # スマホメニュー・キーボード操作
├── js/news.js        # ニュース読込・描画
├── data/news.json    # ニュースデータ（追記式）
├── img/
│   ├── editorial/    # 実写の名古屋写真（出典はcredits.html）
│   ├── brand/        # ブランドのロゴ・キャラクター
│   ├── character/    # マスコット画像（WebP + PNG fallback）
│   └── og/           # OGP用画像
└── robots.txt
```

## ニュースを追加する

`data/news.json` の配列**先頭**に1オブジェクトを追記し、コミット＆プッシュするだけです。

```json
{
  "date": "2026-MM-DD",
  "tag": "リリース | 森道市場 | マガジン | ナゴヤ批評 | ...",
  "title": "タイトル（70字程度まで推奨）",
  "url": "https://..."
}
```

サイト側で日付降順に並び替えるので、追加順序は問いません（先頭推奨）。

## 記事／アプリを追加する

`index.html` の該当セクション（記事は `#articles`、アプリは `#products`）を直接編集します。デザインの一貫性を保つため、テンプレートエンジンは使っていません。

## 技術構成

- バニラ HTML / CSS / Vanilla JS のみ。フレームワーク・ビルドツール無し。
- 画像は WebP（PNGフォールバック）。
- システムフォントのみ（Webフォントなし）。
- PWA / Service Worker は意図的に**入れていません**（ニュース更新を確実に反映するため）。
- 静的HTMLを配信。正規URLはCloudflare Pagesとし、既存のGitHub Pages配信とは公開状態を分けて確認します。

## 2026-11-16 再開発・街の変化ガイド

正規公開先は `https://nagoya-ningen.pages.dev/redevelopment/`。名古屋市16区の主要47件を掲載し、区別の入口と既存の名駅特集へ接続する。各区に掲載案件があることと、各区の全事業の完全網羅は区別する。古い `website-renewal` 作業branchやGitHubの旧配信mainを、現在のCloudflare公開版へ一括統合しない。

- `data/redevelopment.json` が編集データの正本。案件IDはURLになるため保持する。
- `scripts/build_redevelopment.py` が一覧、案件別詳細、16区の専用ページ、サイトマップを通信なしで生成する。配信時は生成済みHTMLを使い、サーバー側処理・新規依存・外部APIは不要。
- 名称・行政区・地域・進捗・用途・予定時期の検索、年別移動を備えた年表、最大3件の比較、ブラウザ内保存、条件共有を備える。保存一覧は端末内だけで、共有リンクには入れない。JavaScriptなしでも全案件と一次資料を読める。
- `wards` は行政区の配列で、区境をまたぐ事業は各区の検索と区ページに含む。`wardGuides` は16区の名称・slug・導入文、`officialRegisters` は照合した公式索引。区別件数の合計には重複があり、全市件数はIDで数える。
- 予定時期の絞り込みはJSTで評価。年度・季節は期間の幅を維持し、解釈できない予定は除外しない。年表は該当案件の過去の経緯も表示する。
- 事実、資料の公表・更新日、確認日、今後の予定を分ける。`milestones.kind` は `actual` / `planned` / `undated`。予定日が過ぎても自動で完了へ変換しない。
- `status` は `review` / `planning` / `construction` / `open`。`open` は完成・供用の集約で、暫定利用・一部開業・建物竣工などの違いは `statusLabel` と本文に明記する。
- 出典には `title` / `url` / `publishedAt` / `verifiedFact` を持たせる。未確認の数字で空欄を埋めず、未定と確認できなかった範囲を区別する。次期開発と暫定施設、工区工期と路線開業を混同しない。

更新時は、対象の公式発表・自治体資料を読み、該当案件の事実・予定・出典・`checkedAt`と`changes`を更新する。ガイド全体の`updatedAt`と`updates`も編集し、生成する。確認日の一括繰上げは禁止。確認後45日超のガイドには、ブラウザ側で最新公式資料の確認を促す表示が出る。自動収集・通知・定期再開は実装していない。
